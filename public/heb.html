מסמך אפיון פרוייקט: SecurityScorecard Findings Dashboard - Cyber Security project

1. מבוא

פרויקט זה הוא דשבורד (לוח מחוונים) אינטראקטיבי המציג ממצאי אבטחה (Findings) שנמשכים באמצעות ה-API של SecurityScorecard. המטרה היא לספק למשתמשים תצוגה מרכזית של ממצאי אבטחה מחברות שונות בפורטפוליו שלהם, מאפשרת סינון, הצגה לפי רמות סיכון (Severity) ופירוט של כל ממצא. הפרויקט בנוי בארכיטקטורת Client-Server תוך שימוש בטכנולוגיות צד-לקוח (Frontend) וצד-שרת (Backend).

2. מטרות הפרויקט

  • מתן ממשק ויזואלי ואינטואיטיבי לצפייה בממצאי אבטחה מ-SecurityScorecard API.
  • סיווג והצגת ממצאים לפי רמות סיכון (High, Medium, Low).
  • הצגת נתונים סטטיסטיים ותרשימים המייצגים את פיזור הממצאים לפי רמות סיכון ופקטורים.
  • אפשור סינון של הממצאים המוצגים על פי קריטריונים שונים (חברה, פקטור, ציון, טווח תאריכים).
  • מתן יכולת "Drill-down" לצפייה בפרטים מלאים על כל ממצא.
  • יכולת ייצוא הנתונים המוצגים (כל הממצאים או ממצאים מסוננים) לקובץ CSV.
  • הגנה בסיסית על הגישה לדשבורד באמצעות מסך התחברות פשוט (Client-side authentication).
  • שימוש ב-API של SecurityScorecard לשליפת נתונים בזמן אמת (או כפי שה-API מספק).

3. טכנולוגיות בשימוש

הפרויקט משלב מספר טכנולוגיות בצד הלקוח ובצד השרת:

  • HTML5: מבנה בסיסי וארגון תוכן הדפים (login.html, index.html).
  • CSS3: עיצוב וסגנון ויזואלי (כולל שימוש ב-Bootstrap ו-CSS מותאם אישית).
  • JavaScript:
    • Client-side (Frontend): טיפול באינטראקציות משתמש, שליפת נתונים מה-Backend API, עיבוד והצגת נתונים בטבלאות ובתרשימים, סינון נתונים מקומי, טיפול ב-Modal (חלון קופץ) לפרטי ממצא, לוגיקת התחברות בסיסית, ויצוא נתונים ל-CSV.
    • Server-side (Backend - Node.js): יצירת שרת Web, ניהול ניתוב (Routing), חשיפת API Endpoint, שליפת נתונים מ-SecurityScorecard API באמצעות HTTP Requests, עיבוד ראשוני של הנתונים והחזרתם ללקוח בפורמט JSON.
  • API (SecurityScorecard): מקור הנתונים החיצוני. הפרויקט מתממשק אליו כדי לשלוף את ממצאי האבטחה.
  • Express: Framework לצד השרת ב-Node.js. משמש ליצירת שרת ה-Web, הגדרת Routes (נתיבים) וטיפול ב-HTTP Requests/Responses.
  • Axios: ספריית Client לביצוע HTTP Requests מצד השרת (ב-app.js) ל-SecurityScorecard API.
  • Dotenv: ספרייה לטעינת משתני סביבה מקובץ .env (משמש לאחסון ה-API Key של SecurityScorecard).
  • Bootstrap 5: Framework CSS פופולרי המאפשר בניית ממשק משתמש רספונסיבי ומעוצב במהירות (Grid system, Components כמו Cards, Tables, Navs, Modals, Dropdowns).
  • Font Awesome: ספרייה לאייקונים (Font-based icons) המשמשת לשיפור המראה הוויזואלי (כפתורים, כותרות).
  • Chart.js: ספריית JavaScript ליצירת תרשימים מותאמים אישית (שימש ליצירת תרשימי ה-Bar וה-Doughnut בדשבורד).
  • jQuery: ספריית JavaScript המשמשת בפרויקט בעיקר לצורך אינטראקציה עם ה-Modal של Bootstrap (ניתן היה להשתמש ב-Bootstrap 5 JS בלבד, אך jQuery נכלל בקוד).
  • MongoDB / Mongoose: הערה חשובה: ספריות אלו מופיעות ב-package.json ו-package-lock.json (התלויות של הפרויקט), אך הן אינן בשימוש בפועל בקוד השרת (app.js) כפי שסופק. הן נכללו ככל הנראה לצורך פיתוח עתידי או ניסויים, אך הדאשבורד הנוכחי לא מתחבר למסד נתונים NoSQL זה ואינו שומר בו נתונים.

4. ארכיטקטורה

הפרויקט מיושם בארכיטקטורת Client-Server:

  1. Client (דפדפן): מבוסס על קבצי HTML, CSS, JavaScript. מציג את ממשק המשתמש, מטפל בלוגיקת ההתחברות (Client-side), מבצע קריאות HTTP GET ל-Backend API, מעבד את הנתונים המתקבלים, מציג אותם בטבלאות ותרשימים, מטפל בסינון וביצוא.
  2. Server (Node.js + Express): מבוסס על הקובץ app.js. משמש כשרת HTTP המגיש את קבצי ה-Frontend הסטטיים. בנוסף, חושף API Endpoint (/api/findings) המשמש כמתווך (Proxy) בין ה-Client ל-SecurityScorecard API. ה-Server מטפל בהזדהות מול SecurityScorecard API (באמצעות ה-API Key), שולף את המידע הרלוונטי ומעביר אותו ללקוח בפורמט סטנדרטי (JSON). הוא אינו מאחסן את הנתונים באופן קבוע במסד נתונים.
  3. External API (SecurityScorecard): שירות חיצוני המספק את ממצאי האבטחה באמצעות REST API.

תרשים ארכיטקטורה פשטני: 


      +------------+      HTTP Request      +---------------+      HTTP Request      +-----------------------+
|   Client   | ---------------------> | Server (Node) | ---------------------> | SecurityScorecard API |
| (Browser)  |                        |    Express    |                        |                       |
+------------+      HTTP Response     +---------------+      HTTP Response     +-----------------------+
     ^                                       |
     |                                       | Serves Static Files (HTML, CSS, JS)
     |                                       |
     +---------------------------------------+

async function loadData() {
    showLoading(true);
    try {
        const response = await fetch('/api/findings');
        if (!response.ok) {

        }

דוגמת קוד - לוגיקת סינון תאריכים: 


if (date) {
    if (!finding.created_at) return false; // Skip if no date

    const findingDate = new Date(finding.created_at);
    const now = new Date();

    if (date === 'today') {
        const todayStart = new Date(now.getFullYear(), now.getMonth(), now.getDate());
        const todayEnd = new Date(now.getFullYear(), now.getMonth(), now.getDate() + 1);
        if (findingDate < todayStart || findingDate >= todayEnd) return false;
    } else if (date === 'week') {
        const sevenDaysAgo = new Date(now);
        sevenDaysAgo.setDate(now.getDate() - 7);
        if (findingDate < sevenDaysAgo || findingDate > now) return false;
    } else if (date === 'month') {
        const thirtyDaysAgo = new Date(now);
        thirtyDaysAgo.setDate(now.getDate() - 30);
        if (findingDate < thirtyDaysAgo || findingDate > now) return false;
    }
}
return true; // Finding passes all filters
  • אוכלוסיית טבלה (populateTables, addFindingToTable): populateTables נקראת לאחר טעינת הנתונים (או החלת סינון) ומנקה את כל גופי הטבלאות. addFindingToTable מקבלת ממצא ומוסיפה שורה חדשה לטבלה הספציפית (High/Medium/Low). יוצרת את ה-HTML עבור השורה כולל כפתור "פרטים" עם data-* attributes לשמירת רמת הסיכון והאינדקס המקורי של הממצא במערך allFindings (חשוב לצורך Drilldown). מוסיפה Event Listener לכפתור "פרטים".

function addFindingToTable(tableId, finding, severity, index) {

    • downloadCSV: מקבלת תוכן CSV ושם קובץ, ויוצרת לינק וירטואלי להורדת הקובץ בדפדפן.
    • setupExportButtons: מגדירה Event Listeners לכפתורי היצוא בתפריט הנפתח. כל כפתור מפעיל את הלוגיקה המתאימה (יצוא הכל, יצוא מסונן, יצוא לפי סיכון) תוך שימוש בפונקציות convertToCSV ו-downloadCSV. יצוא "ממצאים מסוננים" קורא את ערכי המסננים הנוכחיים ומפעיל את filterFinding שוב על כל הנתונים כדי לקבל את הרשימה הנכונה לייצוא.

דוגמת קוד - Event Listener לכפתור יצוא מסונן:

    • שלב ראשון: שליפת רשימת הפורטפוליוז (/portfolios).

7. זרימת נתונים

  1. התחברות:
    • משתמש ניגש לכתובת הבסיס (/).
    • שרת Express מפנה אותו ל-/login.html.
    • הדפדפן טוען את login.html ואת קבצי ה-CSS/JS הנלווים (Bootstrap, Font Awesome).
    • משתמש מזין פרטים ושולח טופס.
    • קוד JavaScript ב-login.html בודק את הפרטים. אם תקין, שומר ב-sessionStorage ומפנה ל-/index.html.
  2. טעינת דשבורד ראשונית:
    • הדפדפן ניגש ל-/index.html.
    • קוד ה-JS בתחילת index.html בודק sessionStorage. אם מאומת, ממשיך. אם לא, מפנה ל-/login.html.
    • הדפדפן טוען את index.html ואת קבצי ה-CSS/JS הנלווים (Bootstrap, Font Awesome, Chart.js, jQuery, Custom CSS).
    • Event Listener על DOMContentLoaded מפעיל את loadData().
    • loadData() מציגה מסך טעינה ומבצעת Fetch ל-/api/findings.
    • שרת (app.js): נתיב /api/findings מופעל. השרת טוען API Key מ-.env. מבצע סדרה של קריאות API אסינכרוניות ל-SecurityScorecard API (פורטפוליוז -> חברות * לכל חברה -> פקטורים/ממצאים). מעבד ומקטלג את הנתונים. בונה אובייקט JSON עם מערכי high, medium, low. מחזיר את ה-JSON ללקוח.
    • Client (דפדפן): מקבל את אובייקט ה-JSON. שומר אותו ב-allFindings. loadData() מסתירה את מסך הטעינה. מעדכנת סטטיסטיקות, מאכלסת טבלאות, מעדכנת תרשימים ומאכלסת מסננים.
  3. סינון:
    • משתמש משנה בחירה במסנן כלשהו.
    • Event Listener מפעיל applyFilters().
    • applyFilters() קוראת את ערכי המסננים. מפעילה את filterFinding על הנתונים הקיימים ב-allFindings כדי ליצור רשימות מסוננות. מרוקנת ומאכלסת מחדש את טבלאות ה-HTML עם הנתונים המסוננים. התרשימים והסטטיסטיקות נשארים ללא שינוי (מציגים את סך הכל).
  4. צפייה בפרטים:
    • משתמש לוחץ על כפתור "פרטים".
    • Event Listener מפעיל showFindingDetails() עם רמת הסיכון והאינדקס המקורי.
    • showFindingDetails() מוצאת את הממצא המלא מהמשתנה allFindings, מאכלסת את ה-HTML של ה-Modal ומציגה אותו.
  5. יצוא:
    • משתמש בוחר אפשרות יצוא.
    • Event Listener מפעיל את הלוגיקה המתאימה (יצוא הכל/מסונן/לפי סיכון).
    • הלוגיקה המתאימה מכינה רשימת ממצאים (כל הממצאים, ממצאים מסוננים על ידי הפעלת filterFinding שוב, או ממצאים רק מרשימת ה-high/medium/low).

    • הקובץ מורד לדפדפן ע"י downloadCSV.
  6. התנתקות:
    • משתמש לוחץ על כפתור "Logout".
